## Research boundary

This is native query discovery, not translation. The drill copy remains authored in each locale; only the search intent, title, description, keywords, visible subtitle, and entity metadata are being tightened.

The workspace `.env` contains `GEMINI_MODEL` only. No Bing Webmaster API credential is present, so no Bing monthly volume is claimed. Google Trends and localized SERPs are directional evidence, not search-volume measurements. GSC and Bing Webmaster exact-match data still need to be connected before making a numeric demand or ranking-probability claim.

## AEO/GEO implementation decisions

- Keep one concise visible drill title and subtitle per locale; avoid stuffing both the title and subtitle with every synonym.
- Keep the existing server-rendered localized guide, benchmark table, 10 FAQ items, HowTo, BreadcrumbList, SoftwareApplication, WebApplication, and VideoGame JSON-LD.
- Add `inLanguage` to the localized application entities so answer engines can associate the entity with the page language.
- Use the researched native query cluster in the metadata and FAQ/guide language already authored for that locale. Do not translate the English page.
- Preserve the self-canonical URL and the existing reciprocal alternate-language map.
- Do not submit URLs to IndexNow/Bing before deployment approval.

## Decision gate

All six markets show active localized SERP demand for the drill’s user intent through native interactive aim-test/training results. This is sufficient to retain the existing localized URLs and optimize them. It is not sufficient to claim a guaranteed #1 ranking, low keyword difficulty, or a numeric monthly search volume until GSC, Bing Webmaster, and a paid/first-party keyword source are connected.
